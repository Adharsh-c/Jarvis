# JARVIS V10.2 — Autonomous Team Reliability

This release builds on the Ollama-only V10.1 baseline. It is packaged separately and does not overwrite V10 or V10.1.

## Included changes

1. **Workflow recovery:** on backend startup, interrupted `in_progress` tasks are returned to `todo` with a recovery note; agent runs left `running` are marked `interrupted`. Project rows left `working` return to `waiting`, and projects with pending `todo` tasks are relaunched.
2. **No blind command replay:** approvals found in `executing` state after a restart are marked `failed` for manual review because the process cannot know whether the command completed externally.
3. **One-way approval decisions:** only `pending` approvals may be approved or rejected; approved actions can transition to executing once; executed/rejected/failed actions cannot be re-approved through the decision endpoint.
4. **Repair-loop resumption:** after a verification repair finishes, the source task is queued again. QA review source tasks are reopened after their queued review fixes complete, so the workflow can retry/review instead of staying permanently blocked.
5. **Change manifest and rollback:** generated file changes now record created/modified state, SHA-256 hashes, and byte counts in task results. If a write in the batch fails, previously touched files in that batch are restored on a best-effort basis.
6. **Automated tests:** approval state-transition tests added, alongside the existing command-policy and command-classification tests.
7. **Local-only AI preserved:** the provider implementation still accepts Ollama only; live web research is not silently claimed.

## Upgrade safely

- Extract to a new folder such as `C:\Users\adhar\project\JARVIS-V10.2-OLLAMA-TEAM`.
- Keep the V10 backup and V10.1 folder unchanged.
- Stop the old backend before testing V10.2.
- Create a fresh Python 3.12 virtual environment and install `backend\requirements.txt`.
- Copy your existing private `backend\.env` only into the new backend folder if you need the same local settings; never share it or put it in a ZIP.
- Back up the current database before migrating any history. Do not copy an actively written SQLite database while the server is running.
- Keep `AI_PROVIDER=ollama`, `AI_AUTO_ORDER=ollama`, and `OLLAMA_ENABLED=true` in the private environment file.
- Verify `/health`, login, project planning, approval/rejection, test execution, restart recovery, and iPhone access before moving to V10.2 permanently.
