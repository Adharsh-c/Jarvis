# JARVIS V10.1 — Ollama Team Reliability Update

## Changes
- Kept the existing Ollama-only provider and local model configuration.
- Added pre-write validation for generated file batches, including duplicate-path rejection, `.git` and `.env` protections, and per-file/total batch size limits.
- Made command-kind classification depend on actual command text rather than an AI-provided label.
- Made approval execution single-use by transitioning approved items to executing and then executed/failed.
- Resumed the dependency-aware project orchestrator after approved test commands finish, allowing dependents or bounded repair tasks to proceed.
- Added regression tests for test/build/install command classification.
- Removed populated `.env` files, virtual environments, caches, databases, and Git metadata from this distributable archive.

## Verification performed in the build environment
- Python compilation: passed for all backend application Python files.
- Unit tests: 9 passed, including existing command-policy tests and new command-classification tests.

## Not verified here
- Windows runtime behavior on the user's laptop.
- Live Ollama generation, existing local account/database migration, iPhone LAN connectivity, voice agent, and desktop-agent integration.

## Safe installation
Extract this release into a new folder rather than over the currently working installation. Create `backend/.env` from `backend/.env.example`, set fresh local secrets, install backend requirements, and test the new instance before migrating data or switching the iPhone URL.
